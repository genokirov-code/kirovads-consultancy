# GTM setup — KirovAds (GTM-TP88RP2F) with Consent Mode v2

The website already does the consent part:

- Every page sets Google Consent Mode v2 **defaults to denied** before GTM loads
  (`ad_storage`, `ad_user_data`, `ad_personalization`, `analytics_storage`),
  turns on `ads_data_redaction`, and immediately applies the visitor's saved choice.
- The cookie banner (Accept all / Reject all / Settings → Analytics, Marketing)
  sends `gtag('consent','update', …)` and pushes this dataLayer event:

```js
{ event: 'cookie_consent',
  consent_action: 'accept_all' | 'reject_all' | 'custom' | 'auto_accept',
  consent_analytics: 'granted' | 'denied',
  consent_marketing: 'granted' | 'denied' }
```

- After a successful form submission the thank-you page pushes
  `{ event: 'audit_form_complete' }` (EN and BG).

The live container is currently **empty** (no tags published). `kirovads-gtm-import.json`
adds everything below.

## What the import contains

| Tag | Fires on | Consent |
|---|---|---|
| Google Tag - GA4 | Initialization – All Pages | Built-in (Consent Mode) |
| GA4 Event - generate_lead | `audit_form_complete` | Built-in |
| Google Ads - Conversion Linker | All Pages | Built-in |
| Google Ads - Lead Conversion | `audit_form_complete` | Built-in |
| Meta Pixel - Base + PageView | All Pages **and** `cookie_consent` with marketing = granted (once per page) | Requires `ad_storage` + `ad_user_data` |
| Meta Pixel - Lead | `audit_form_complete` (runs the base tag first) | Requires `ad_storage` + `ad_user_data` |

The second Meta trigger matters: on a visitor's first page, consent is still denied when
the page loads, so the pixel is blocked. When they accept, `cookie_consent` fires and the
pixel loads on that same page.

Variables to fill in (Variables → User-Defined):

| Variable | Replace with | Where to find it |
|---|---|---|
| Const - GA4 Measurement ID | `G-…` | GA4 → Admin → Data streams → Web |
| Const - Google Ads Conversion ID | numbers only, without `AW-` | Google Ads → Goals → Conversions → your lead action → Tag setup → Use GTM |
| Const - Google Ads Conversion Label | the label | same screen |
| Const - Meta Pixel ID | the pixel number | Meta Events Manager → Data sources |

## Steps

1. **GTM → Admin → Import container** → choose `kirovads-gtm-import.json`
   → workspace: *New* (e.g. "Consent Mode setup") → **Merge** → *Rename conflicting
   tags, triggers and variables* → Confirm.
2. Open **Variables** and replace the four placeholder values above.
   If you don't use one platform yet, pause or delete its tags instead.
3. **Admin → Container settings → Enable consent overview** (lets you check consent per tag
   via the shield icon on the Tags page).
4. Click **Preview**, open the site, then check in Tag Assistant:
   - First page, before choosing: the **Consent** tab shows all four signals *Denied* on
     *Consent Default*; Meta Pixel shows *Blocked by consent*.
   - Click **Reject all**: signals stay *Denied*; Meta Pixel doesn't fire.
   - Clear site data, reload, click **Accept all**: *Consent Update* shows *Granted*, and
     "Meta Pixel - Base + PageView" fires on the `cookie_consent` event.
   - Footer **Cookie settings** → Analytics on, Marketing off → Save: `analytics_storage`
     granted, the three ad signals denied.
   - Submit the contact form once: on the thank-you page `audit_form_complete` fires
     GA4 *generate_lead*, the Google Ads conversion and (with marketing consent) Meta *Lead*.
5. **Submit → Publish.**
6. In **GA4 → Admin → Events**, mark `generate_lead` as a **key event**.
   In **Meta Events Manager**, verify the `kirovads.com` domain.

## If the import doesn't work

The import was generated by hand-coded JSON and couldn't be tested against your account.
If GTM rejects it, create the same tags manually using the tables above:
Google tag (type *Google Tag*), GA4 event (type *Google Analytics: GA4 Event*),
Conversion Linker, Google Ads Conversion Tracking, and two *Custom HTML* tags with the
Meta code from the JSON file. For the two Meta tags set
*Advanced settings → Consent settings → Require additional consent* →
`ad_storage` and `ad_user_data`.
